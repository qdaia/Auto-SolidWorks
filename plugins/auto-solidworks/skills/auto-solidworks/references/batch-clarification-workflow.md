# 集中澄清与必要审核

本合同优化代理的识图、尺寸绑定与工具编排。版本为 26.10.11mini，基于本地整合候选26.10.12实现。既有编译接口新增readiness回执：来源缺口与代理修复项集中呈现；原验证条件保留。这不是自动尺寸识别器，原生全过程提速未实测。

## 默认顺序

原图与全部相关细节检查 → 特征/尺寸/基准表与问题台账 → 集中澄清（有阻塞项时）→ 完整尺寸绑定与一次编译 → 原生建模 → 读取保存重开与完整必要验收回执 → 交付。

来源解释、遗漏覆盖、方向和风险校验并入建模前内部汇总；保存重开、实体有效性、关键尺寸和来源几何检查并入交付前内部汇总。汇总是减少代理重复复盘，不是跳过工具内部的检查或把两次原生测量合并成一次。

## 首次识图与集中提问

1. 先看全图、每个来源页、正投影视图、轴测图和全部非空细节。建立一份共享表：特征 ID、视图与定位、标注原文、单位、物理轴与基准、直接值或几何推导、操作字段、独立验收目标。文字和尺寸由AI直接从原图识别；必须核对尺寸端点、对象和轴向。
2. 尺寸有三类处理：清晰源标注直接绑定；能够由已知尺寸推导的值记录推导并绑定；无法唯一确定且影响孔位置/直径、厚度、深度、通盲、槽范围、圆弧或拓扑的值进入阻塞问题台账。跨视图矛盾也进入台账。代理自己的 JSON 字段错误、尺寸名称查找、自身误读或缺少 API 知识自行修复，不问用户。
3. 在首次全图核对后，把所有当前已知阻塞项按同一物理问题去重，一次提出。一个问题可关联多个尺寸 ID 与操作。提问说明具体部位、相关视图、已确定事实、仍缺信息、对模型的影响；有源证据支持的不同解释才列选项，否则要求明确数值和单位。不能编造默认值或把任一候选解释当成授权。
4. 无阻塞项直接编译，不询问已标尺寸、不要求批准完整计划。已有会话修正与授权持续有效；答案绑定到受影响的来源事实、操作参数和验收目标。仅回答部分问题时，只补问未回答项；沉默不能视为答案。等待回答时可整理无依赖的草稿，不执行依赖未知关键值的原生操作。
5. 一次集中提问是减少常规交互的目标，不保证永不补问。后续发现新的原图反证、真正缺尺寸或需要改变源标称值时，暂停相关部分，说明新证据并集中补问。新的编译器或执行器故障先自行定位，不能伪装成用户必须回答的图纸问题。

问题台账是任务内部工作记录，可用 Q01 等 ID 与下面的字段；它不是新增 MCP 参数，不得塞入不支持的 drawing_context 字段：

| ID | 特征/尺寸 ID | 源视图与定位 | 已知与缺失信息 | 待确认问题 | 受影响操作/检查 | 状态/答案依据 |
|---|---|---|---|---|---|---|
| Q01 | 当前实际 ID | 实际页码与区域 | 已检查原图的事实 | 一句具体问题 | 当前实际引用 | 未解决/真实答案 |

## 建模前只汇总一次，校验继续保留

- 将特征、尺寸、解释假设与反证一次整理为 drawing_context。require_complete_bindings=true、require_interpretation_review=true 不变；未解决关键事实不能改成 Stated 或 Derived。所有候选和来源区域仍实际复查。candidate_ids 只能合并已看过、判定和依据相同的候选。
- 同一项源事实可供多个操作和检查引用，但每个受影响的字段都有绑定。不要复制出彼此冲突的尺寸表。未经授权不改源标称值；偏差必须保留原标称、执行值、推导、理由和实际授权。
- 只读当前操作需要的合同一次。复杂/多轮任务复用读图待审上下文句柄，几何草稿另存一次；每批修正用 JSON Patch 同步更新操作、来源绑定和独立验收。简单一次性任务可直接交完整 draft，避免多余存储调用。
- 完成全部必要来源审查后，一次编译；读取全部错误与相关警告，摘要截断时按 next_offset 读完完整 diagnostics，再一次修正当前全部已知可修项。修正后重编译是必要步骤，不按前 12 条失败逐个循环，也不把信息性方向轨迹当成额外用户审批。
- 原生执行前核对孔/切除/旋转方向、引用范围、草图驱动与约束、零厚度、全部未注圆角范围、独立全模型库存及关键局部几何。普通建模不先 health、不要求注册/批准计划，不重复获取完整 IR，也不增加无必要 dry-run。无法独立确定的关键库存不能从生成模型反填。

## 交付前一次证据汇总

- 原生保存前及重新打开后的独立检查由原执行器继续执行，包括重建、实体故障和声明的来源/几何要求。读取全部必要 verification/checks；摘要不完整时分页续读，而不是重新运行检查。
- 同一文件内容、配置/源修订、验收要求和完整回执均未改变，且已证明成功保存重开时，复用该证据。文件或配置变化、新检查、缺失/无法测量证据仍需实测。不能把旧回执用于修改后的文件。
- 请求 STEP/STP 时另验收导出几何；请求工程图/PDF 时重开工程图并查看全部 PDF 页面。只请求模型时不为了审查仪式额外导出工程图；现有要求必须用投影/剖面证明的特征仍需相应检查，不能用包围盒或有限测点替代。
- 失败只改受影响的草稿与上下文，复用身份一致且已成功验证的稳定检查点。pending/outcome_unknown 保留 request_id 并查询持久回执，不重复提交原生修改。完整检查未通过时保留失败与未验证范围，不交付为合格成品。

## 防止把流程优化当成速度证据

分别记录实际看图/绑定、编排、用户等待、原生执行与返工、保存重开/验收的时间；总墙钟保留用户等待，另列代理工作时间。用户答案后重新看图的时间归识图复盘。重复调用和传输字符的减少可计数，不等于实测 token 或完整建模加速。

速度对照需相同输出、关键尺寸、圆角和验收范围；独立全过程对照不共用另一任务的识图答案。没有对照实测时只报告本轮合同改变和离线兼容结果，不承诺时间或百分比。

## 编译回执中的集中处理清单

失败的cad_create_model_plan返回readiness摘要与完整回执句柄。`/readiness/source_gaps`列出声明为Unknown/Assumed的关键事实及已有解释冲突，先复查源图再决定是否问用户；它不是自动问答或缺尺寸认证。`/readiness/error_groups`按相同代码、路径和消息合并重复诊断并保留全部原诊断索引，用于代理批量修复。摘要截断时按next_offset读完对应数组。未知值不作为推荐答案，成功与可执行plan_id仍由原编译器决定。
