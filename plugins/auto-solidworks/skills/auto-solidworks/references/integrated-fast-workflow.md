# 独立识图与建模的默认流程

当前任务同时遵循 [集中澄清与必要审核](batch-clarification-workflow.md)：先完成首次全图核对，当前已知阻塞问题去重集中询问；仅为新增反证或新缺失项补问。两次内部汇总保留全部来源绑定、保存重开与原生有效性门禁，不增加用户计划审批。

本地整合候选，以 26.10.12 的运行时和严格验收为底座。目标是减少识图后的合同编排、重复输入和失败返工。未做新的独立全过程重测，不能据此声称某个加速百分比。

## 识图与编排

1. 每个独立建模任务从原始图片、用户尺寸修正和本任务自己的计时起点开始。不得读取另一任务的识图结果、坐标表或已解决草稿。计时包含技能/合同阅读、图像分析、编排、失败与验收；另外记录工具调用和等待时间。
2. 先一起看正投影视图与轴测图，以简短的特征/尺寸表确定孔、凸台、连接板、加强筋、槽和所有圆角的解释。先处理跨视图冲突，再展开长合同。每个被排除的解释仍要有定位明确的源图反证。用户对尺寸的修正优先于 OCR。
3. 使用 `cad_read_drawing` 本任务生成的不可变库存，并读实际原图和所有非空区域。默认读取工具直接返回 `review_workspace.drawing_context_input_id` 与 `worklist_artifact_id`，用 `cad_read_result` 分页查看与 `cad_store_model_input` 增量填写。需要独立文件助手时可运行插件内的 `scripts/prepare-review-workspace.py INVENTORY NEW_OUTPUT --inventory-sha256 RECEIPT_SHA`，自动建立有来源哈希的待审上下文和按区域组织的工作清单。该助手只整理 ID 和来源，所有语义判断保持待审；不能把运行成功视为已经识图。
4. 实際逐区审查后，对同一判定、同一依据的候选使用既有 `candidate_ids` 批量评审。保留每个原始 ID、区域、OCR 冲突、非建模理由和重复关系；不因为候选多就全部当噪声。无需反复手写同一库存 ID 或整份评审数组。
5. 将完整 `drawing_context` 通过 `cad_store_model_input` 存一次；把不包含上下文的几何草稿另存一次。编译使用 `draftId` 和 `drawingContextId`。只读需要的 `cad_get_contract` 段；已阅读的相同合同不重复获取。
6. 首次原生执行前检查 `EXTRUDE_DIRECTION_TRACE`、`HOLE_DIRECTION_TRACE`，与源实体一侧和槽宽核对；草图需要导出/验收的驱动尺寸应在此时确定。列清所有未注 R3 的适用连接，不留到最后才补做。整体边界计数必须独立推导；推导不确定时保留未解决状态，不能猜数或从生成模型回填。

## 执行与验收

- 修改通过既有存储输入的 JSON Patch 派生新 ID；仅发送有变化的字段，更新来源解释时单独派生上下文。每批最多 200 项。不要重发不变的候选库存、来源解释和几何草稿。
- 设置当前任务自己的 `source_revision_id`，保留来源/操作前缀与检查点身份。发生不确定结果，先读持久回执；不得直接重复原生请求。
- 既有保存/重开回执已涵盖的检查，按需分页读取。文件未变时不为了获取摘要再做相同的原生验收。新的检查或文件变化仍须实测。
- 同一次局部验收内，相同面索引和完全相同的测点复用 `IFace2.GetClosestPointOn` 结果。逐面枚举、不同公差、法向、面积、失败状态仍单独评估；新一轮检查和保存重开重新测量。此机制不是近似采样或跨模型缓存。
- 直接查看生成 PDF 的完整页面。视图 BMP 被裁剪时不能证明视觉覆盖完整；不要把整份生成图重新送入 OCR 作为页面查看的替代。

## 对比记录

总耗时 = 独立识图与必要准备 + 编排 + 原生调用与失败恢复 + 保存重开 + 补充验收与视觉检查。记录各阶段及总墙钟时间。与旧版比较时同时报告最终特征/圆角、来源冲突、未通过项目及原生有效性。不同质量边界或共用识图结果的样本不能用于证明独立全过程加速。
