Use `cad_export_drawing(inputPath, nativePath, pdfPath, templatePath?, layout?)` on a saved local `.SLDPRT` or `.SLDASM`. All paths must be absolute; outputs must not exist. A dirty open source is rejected. Assemblies require saved, resolved, unmodified active components; component hashes are checked after export. The default template search prefers installed `gb_a3.drwdot`, then the configured native drawing template. An explicit template must exist and end in `.drwdot`; layout overrides its paper geometry.

`cad_build_assembly` invokes this exporter automatically after saving/reopening the assembly, using matching sibling `.SLDDRW` and `.pdf` paths. Its nested `drawing` result records drawing verification; overall success is false when drawing export fails. Assembly views import native assembly and component dimensions using SolidWorks Model Items, including dimensions in hidden model features. Component dimension names retain the source-model suffix to avoid conflating different files. Their parameter schedule contains assembly-level parameters only, not a BOM or separate component detail drawings.

Defaults remain A3 first-angle Front/Top/Left/Isometric. `layout` supports `sheet_width_mm`, `sheet_height_mm`, `first_angle`, `views`, `margin_mm`, `view_gap_mm` and `schedule_row_height_mm`. Standard views include Front/Top/Left/Right/Bottom/Back/Isometric; Front is required. Positions and scale-fit cells are computed from paper geometry; third-angle switches the Top/side placement. Parameter schedules paginate according to usable sheet capacity, with all pages selected for PDF export. The saved native drawing is reopened and checked for every sheet's projection/size, the complete view/model reference inventory, exact dimension identities/values/units/multiplicity/placement and every schedule entry's identity/value/unit/page. Check `sheets`, `schedule_entry_count` and `schedule_reopened` as well as `dimensions_reopened`. No placed native dimensions fails export. A schedule is not full drawing or manufacturing equivalence.

English and Chinese standard model view names are resolved from the actual source. Other localized installations must expose a recognized standard name; an unresolved view fails explicitly. Multi-body parts are retained. There is no 44-parameter cap. Existing outputs are never overwritten; failed partial outputs remain for diagnosis. Complex dimension collisions still require visual native/PDF acceptance; this changed exporter was not run in SolidWorks in the current revision.

Inspect the PDF pages before delivery. Imported dimensions can include construction or feature dimensions that are not useful manufacturing constraints. Complex hidden-line geometry, long construction centerlines and crowded dimensions may require further native drawing editing. `source_dimensions` includes unique source-level parameters (assembly-level only for assemblies), `imported_dimension_names` records those inserted into views, and `unplaced_dimension_names` records schedule-only parameters. No missing critical dimension is invented. Geometrically meaningful positions can still be absent from an underdefined source sketch even when every stored parameter is listed.

For model-derived regression data, retain `drawing_origin=generated_from_reference_model`, source hashes and explicit reference authorization. These drawings are useful for extraction, units, coverage and geometry regression; they do not establish blind reconstruction accuracy on independently supplied drawings.

To read the four-view page, use `cad_read_drawing` with `pageNumbers:[1]` and inspect its actual image. Read the parameter schedule separately when the task allows the reference model's data. Do not treat the schedule as geometry, or silently use it as independent source evidence. Native PDF extraction follows glyph baselines and preserves rotation; OCR conflicts remain conflicts in dimension candidates. Auxiliary dimension candidates do not certify attachment, even if their numeric value agrees with a reference.
